# ODDYN

Русскоязычное Android-приложение для прематч-аналитики футбола, хоккея и тенниса. Первый выпуск 0.1.0 работает на Android 8.0 и новее. При первом запуске выбран локальный режим **«Демо»**. Матчи, сценарии и котировки в нём условные.

## Первый запуск

1. На главной выберите дату по МСК и нажмите **«Найти ставки»**.
2. Откройте матч, посмотрите условия и риски рынка. Сохраните прогноз или добавьте рынок в экспресс.
3. Откройте **«Экспрессы»**, проверьте совместимость и сохраните подборку. Из разных режимов складываются отдельные черновики.
4. В **«Истории»** есть журнал прогнозов и отдельный журнал купонов, которые вы фактически разместили. Купон попадает в статистику после ручного ввода расчёта и фактической выплаты.

## Компоненты

| Путь | Назначение |
| --- | --- |
| `android/app/` | Kotlin, Material 3 и Compose, навигация, ViewModel, клиент API, Room и DataStore |
| `android/app/schemas/` | Зафиксированная схема Room для будущих миграций |
| `backend/oddyn/` | FastAPI, контракты Pydantic, реестр поставщиков, адаптер футбольного расписания и расчёт рынка |
| `shared/demo.json` | Единый демосценарий для Android и FastAPI |
| `.github/workflows/android.yml` | Сборка debug APK, JVM-тесты, Android Lint, компиляция инструментальных тестов и тесты API |

## Android

Для сборки нужны JDK 17, Android SDK 36, Build Tools 36.0.0 и Gradle Wrapper из репозитория.

```bash
sdkmanager 'platforms;android-36' 'build-tools;36.0.0'
./gradlew assembleDebug testDebugUnitTest lintDebug assembleDebugAndroidTest
```

После успешной сборки APK находится в `android/app/build/outputs/apk/debug/app-debug.apk`. Workflow сохраняет файл `ODDYN-debug.apk` как артефакт `ODDYN-debug-apk`. Сборка и первый запуск работают без сервера, Google Sheets и токенов. Debug-подпись зависит от среды сборки. При обновлении поверх APK с другой подписью Android потребует отдельную установку, а удаление приложения стирает локальный журнал.

Инструментальные тесты запускаются на чистом эмуляторе или тестовом устройстве командой `./gradlew connectedDebugAndroidTest`. Тестовый сценарий переключает режим и записывает локальные данные. Используйте тестовую установку.

## FastAPI

Из корня репозитория с Python 3.12:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
cd backend
python -m pytest -q
python -m uvicorn oddyn.main:app --host 127.0.0.1 --port 8000
```

OpenAPI доступен по `/docs` и `/openapi.json`. За пределами локальной разработки используйте HTTPS, один процесс для соблюдения лимита бесплатного источника и конфигурацию окружения на стороне сервера. В debug-версии для эмулятора допустим адрес `http://10.0.2.2:8000`. При отладке через `adb reverse tcp:8000 tcp:8000` подойдёт `http://127.0.0.1:8000`. Вводить адрес нужно в настройках Android.

| API v1 | Назначение |
| --- | --- |
| `GET /v1/health` | Версия контракта и состояние поставщиков |
| `GET /v1/events?date=YYYY-MM-DD&mode=real` | Расписание за день МСК, опционально `sport=football\|hockey\|tennis` |
| `GET /v1/events/{event_id}?date=YYYY-MM-DD&mode=real` | Событие, источники, факты, условия рынков, риски |
| `POST /v1/analytics/market` | Расчёт по переданному рынку с проверкой структуры котировки и данных модели |

На обеих сторонах расчёт ведётся в десятичных числах. Безубыточный порог `1/k` и `EV = p × k − 1` применяются к бинарному расчёту. Для EV нужны метод, размер выборки, описание валидации и источники вероятностной модели. Реальная котировка требует HTTPS-источник, букмекера, время наблюдения, линию и условия. Приложение использует котировки до часа после наблюдения. Сохранённые записи содержат исходный снимок. Экспресс из разных матчей показывает произведение действительных котировок как теоретическую цену. Для плеч одного события нужны условия и цена комбинированного рынка. Для заведомо взаимоисключающих исходов сохранение экспресса блокируется. Совместная вероятность и EV экспресса в выпуске 0.1.0 отсутствуют.

## Источники и охват

- **Football-Data.org.** Включите через переменную `FOOTBALL_DATA_TOKEN` на сервере. Бесплатный тариф даёт расписание 12 турниров с возможной задержкой и лимитом 10 запросов в минуту. Сохраняются время проверки и URL конкретного матча. Фильтр включает подтверждённый статус `TIMED` и предстоящие события выбранного дня МСК. Адаптер не запрашивает котировки, составы и травмы. [Тариф](https://www.football-data.org/pricing) · [Покрытие](https://www.football-data.org/coverage) · [Документация](https://docs.football-data.org/general/v4/match.html) · [Условия](https://www.football-data.org/about)
- **OpenFootball.** Открытые календари и результаты без ключа. В текущий выпуск не подключены. Для использования в прематче потребуется проверить полноту времени начала и порядок обновления каждой лиги. [Данные](https://github.com/openfootball/football.json)
- **НХЛ и теннис.** Условия NHL требуют разрешения на автоматизированный сбор. Исторические наборы ATP/WTA Джеффа Сакманна имеют некоммерческую лицензию и не предоставляют гарантированного расписания будущих матчей. Реальные поставщики хоккея и тенниса пока не подключены. [Условия NHL](https://www.nhl.com/info/terms-of-service) · [Архив и лицензия ATP/WTA](https://github.com/Aneeshers/tennis-sackmann-archive)
- **Букмекерские котировки.** Реальный поставщик отсутствует. В реальном режиме приложение покажет расписание и наличие данных от настроенного источника.

## Хранилище и решения первого выпуска

Имена реестров перенесены из таблицы проекта. В Room хранятся прогнозы (`forecasts`), купоны (`tickets`), экспрессы и плечи (`expresses`, `express_legs`), очередь и контрольные точки (`analysis_queue`, `checkpoints`), наблюдения рынка, аудит и реестр источников. Статистика вычисляется по фактически рассчитанным купонам в рублях. Плечи экспресса в ней отдельно не учитываются. Win Rate использует полные выигрыши и проигрыши. Во всех финансовых метриках используется введённая пользователем фактическая выплата, включая досрочный расчёт.

День поиска, охват, обработанные и ожидающие события сохраняются локально. Обновление строки задачи, наблюдений и checkpoint выполняется одной транзакцией. Незавершённая очередь продолжается с первой ожидающей задачи. Реальные события при продолжении сверяются с расписанием сервера. Google Sheets отделён интерфейсом подключения. В первом выпуске он всегда показывает фактическое состояние «не подключён». Backend не принимает пользовательские журналы и работает без PostgreSQL.

Фирменные цвета и название взяты из архива проекта. Экран и иконка запуска используют надпись ODDYN. Оригинал утверждённой эмблемы профиля отсутствовал в архиве. Для коэффициентов, командных названий и ссылок сохранена возможность расширить словарь и модель источников без изменения локального журнала.
